# 보안 노트

이 앱은 **백엔드가 없는 정적 사이트**(Vite 빌드 → Render 정적 배포 + Firestore 직접 접근)다.
그래서 구조적으로 클라이언트를 신뢰할 수밖에 없는 지점들이 있다.
동아리 내부용이라는 신뢰 모델에서는 대체로 수용 가능하지만, **무엇이 막히고 무엇이 안 막히는지**는
정확히 알고 쓰는 게 좋다.

---

## 1. 구조적으로 못 막는 것 (알고 쓸 것)

| 항목 | 실제 위험 | 왜 못 막나 |
|---|---|---|
| **학번만으로 로그인** | 남의 학번을 알면 그 사람으로 로그인 가능 | 비밀번호/세션 검증을 할 서버가 없음 |
| **관리자 게이트** | 개발자도구로 상태를 바꾸면 관리자 화면 진입 가능 | 클라이언트 검사는 모두 우회 가능 |
| **퀴즈 정답** | Firestore 의 `quizzes` 문서에 정답이 들어 있어 네트워크 탭에서 확인 가능 | 채점이 브라우저에서 일어남 |
| **성적/진도 위조** | 콘솔에서 Firestore SDK 로 직접 쓰기 가능 | 규칙이 사용자를 식별하지 못함 |
| **Gemini API 키** | 번들에 포함되어 추출 가능 → 남이 내 할당량을 씀 | 브라우저에서 직접 호출하기 때문 |
| **영상 업로드 토큰** | 번들에 포함 → 유출 시 서버에 업로드 가능 | 위와 동일 |

> 스크린샷은 웹에서 **원천적으로 감지 불가**하다. 특히 모바일. 로그로 남는 것은
> PrintScreen 키(Windows), Cmd+Shift+3/4/5(macOS) **입력**뿐이며, 실제 캡처 여부는 알 수 없다.

## 2. 이번에 실제로 막은 것

- **관리자 비밀번호 평문 노출** → `VITE_ADMIN_PASSWORD_HASH`(SHA-256)로 교체.
  번들에서 비밀번호를 그대로 읽어가는 건 이제 불가능하다. 시도 5회 실패 시 5분 잠금도 추가.
- **업로드 토큰과 관리자 비밀번호 분리** → `VITE_VIDEO_UPLOAD_TOKEN`.
  예전엔 관리자 비밀번호가 업로드 토큰으로 재사용돼, 토큰 유출 = 비밀번호 유출이었다.
- **비디오 서버 임의 파일 업로드** → mp4/webm/ogg/mov/m4v 만 허용.
  예전엔 `.html`/`.svg` 를 올려 그 도메인에 **저장형 XSS** 를 심을 수 있었다.
  추가로 `X-Content-Type-Options: nosniff`, 응답 CSP, 확장자를 MIME 에서 결정(경로 탈출 차단),
  IP당 레이트 리밋, `/list` 토큰 보호, 타이밍 안전 토큰 비교.
- **Firestore 규칙** → `firestore.rules` 추가. 화이트리스트 + 성적/로그 **삭제 금지**.

## 3. 설정 방법

### 관리자 비밀번호 해시 만들기

```bash
printf '원하는비밀번호' | shasum -a 256
```

출력된 64자리 hex 를 `.env` 에 넣는다:

```env
VITE_ADMIN_PASSWORD_HASH=여기에64자리hex
```

기존 `VITE_ADMIN_PASSWORD`(평문)도 계속 동작하지만 **하위 호환용**이다. 해시로 옮기고 평문은 지울 것.
Render 를 쓴다면 대시보드의 Environment 에서도 동일하게 교체해야 한다.

### 영상 업로드 토큰

```env
VITE_VIDEO_UPLOAD_TOKEN=길고-무작위인-문자열
```

같은 값을 비디오 서버의 `UPLOAD_TOKEN` 환경변수에 넣는다. **관리자 비밀번호와 절대 같게 쓰지 말 것.**

### Firestore 규칙 배포

```bash
firebase deploy --only firestore:rules
```

또는 Firebase 콘솔 → Firestore → 규칙 탭에 `firestore.rules` 내용을 붙여넣기.

> 이 규칙은 `students` / `quizzes` / `courses` / `announcements` 쓰기를 **차단**한다.
> 관리자 화면에서 퀴즈·코스·팀원을 저장하려면 그 부분을 `allow write: if true;` 로 완화하거나
> (= 지금까지와 동일한 위험), 아래 4번의 Auth 도입이 필요하다.

## 4. 제대로 잠그려면 (다음 단계)

1. **Firebase Auth 도입** — 익명 로그인이라도 붙이면 `request.auth.uid` 가 생긴다.
   학생 문서에 uid 를 매핑하고, 규칙을 `request.auth.uid == resource.data.uid` 로 좁힌다.
2. **커스텀 클레임으로 관리자 구분** — `request.auth.token.admin == true` 인 경우에만
   `quizzes`/`courses`/`students` 쓰기 허용. 클라이언트 비밀번호 게이트를 완전히 대체한다.
3. **채점을 Cloud Functions 로 이전** — 정답이 클라이언트에 내려가지 않게 되고,
   Gemini 키도 서버에만 두게 되어 위 1·5번 항목이 동시에 해결된다.
4. **진도/부정행위 로그도 Functions 경유 기록** — 위조 차단.

1~2번만 해도 실질적인 위험 대부분이 사라진다.
