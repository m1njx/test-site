# Firebase Auth 도입 — 설정 순서

로그인을 **학번 + 비밀번호**로 바꾸고, 권한을 서버(Firestore 규칙)에서 강제하기 위한 설정입니다.
Firebase **무료(Spark) 플랜에서 그대로 동작**합니다. 카드 등록도 필요 없습니다.
(유료인 건 SMS 인증뿐인데, 이 앱은 쓰지 않습니다.)

순서대로 따라가면 15분 정도 걸립니다. **3번까지 마치기 전에는 규칙을 배포하지 마세요.**

---

## 1. 이메일/비밀번호 로그인 켜기

Firebase 콘솔 → **Authentication** → **시작하기** →
**Sign-in method** 탭 → **이메일/비밀번호** → 사용 설정 → 저장.

> 이메일 링크(비밀번호 없는 로그인)는 켜지 않아도 됩니다.

## 2. 관리자 계정 만들기

관리자도 **팀원 명부에 있어야** 로그인할 수 있습니다.

1. 앱에서 (아직 예전 방식으로 로그인이 된다면) 관리자 → **팀원 관리**에서 본인 학번을 등록합니다.
   이미 등록돼 있다면 넘어갑니다.
   - 이메일을 함께 넣으면 비밀번호를 잊었을 때 스스로 재설정할 수 있습니다. 넣어두길 권합니다.
2. 로그아웃 후 본인 학번으로 로그인 → **비밀번호 설정** 화면이 뜨면 비밀번호를 만듭니다.
3. Firebase 콘솔 → **Authentication** → **Users** 에서 방금 만들어진 계정의 **UID** 를 복사합니다.

## 3. 관리자 권한 부여

Firebase 콘솔 → **Firestore Database** → 컬렉션 시작:

- 컬렉션 ID: `admins`
- 문서 ID: **2번에서 복사한 UID**
- 필드: 아무거나 하나 (예: `name` = `"강민제"`)

이 문서가 있는 사용자만 관리자 화면에 들어갈 수 있습니다.
`admins` 컬렉션은 규칙상 **앱에서 만들 수 없고 콘솔에서만** 만들 수 있어서,
개발자도구로 상태를 바꿔도 관리자가 될 수 없습니다.

> 관리자를 더 두려면 그 사람의 UID 로 문서를 하나 더 만들면 됩니다.

## 4. 보안 규칙 배포

```bash
firebase deploy --only firestore:rules
```

또는 콘솔 → Firestore → **규칙** 탭에 `firestore.rules` 내용을 붙여넣고 게시.

**반드시 3번을 먼저 끝내세요.** 관리자 문서 없이 규칙을 배포하면
퀴즈·코스·팀원 저장이 전부 막혀서 관리자 화면을 쓸 수 없게 됩니다.

## 5. 기존 팀원 안내

기존 팀원들은 **첫 로그인 때 비밀번호를 직접 만듭니다.**

> "이제 학번 입력 후 비밀번호를 넣어야 해요.
>  처음 로그인하면 비밀번호 설정 화면이 나오니 원하는 비밀번호(6자 이상)를 만들어주세요."

관리자 화면의 팀원 목록에서 **가입 완료 / 가입 전** 배지로 누가 아직 안 만들었는지 확인할 수 있습니다.

---

## 자주 겪는 상황

**Q. 팀원이 비밀번호를 잊었어요.**
- 명부에 **이메일이 있으면**: 로그인 화면에서 "비밀번호를 잊으셨나요?" → 재설정 메일.
- 이메일이 없으면: Firebase 콘솔 → Authentication → Users → 해당 사용자 →
  **비밀번호 재설정** 또는 **사용자 삭제**. 삭제한 경우 Firestore 의 `students/{학번}` 문서에서
  `uid` 필드도 지워야 다시 "가입 전" 상태가 되어 새로 비밀번호를 만들 수 있습니다.

**Q. 관리자 화면 버튼이 안 보여요.**
- `admins/{내 UID}` 문서가 있는지 확인하세요. UID 는 Authentication → Users 에서 볼 수 있습니다.
- 문서를 만든 뒤에는 **로그아웃 후 다시 로그인**해야 반영됩니다.

**Q. 저장할 때 "Missing or insufficient permissions" 오류가 납니다.**
- 관리자 권한(3번)이 없는 상태에서 규칙이 배포된 경우입니다. `admins` 문서를 만들고 재로그인하세요.

**Q. 예전처럼 학번만으로 쓰고 싶어요.**
- Firebase 설정(`VITE_FIREBASE_*`)이 없으면 앱은 자동으로 예전 방식(Mock 모드)으로 동작합니다.
  운영 환경에서는 권장하지 않습니다.

## 이걸로 해결되는 것 / 남는 것

| | Auth 도입 전 | 도입 후 |
|---|---|---|
| 남의 학번으로 로그인 | 가능 | **막힘** |
| 관리자 화면 무단 진입 | 가능(클라이언트 검사) | **막힘**(서버 검증) |
| 성적·진도·응시기록 위조 | 가능 | **막힘**(본인 것만 쓰기) |
| 성적/로그 삭제 | 가능 | **막힘**(규칙상 삭제 불가) |
| 퀴즈 정답 열람 | 가능 | 여전히 가능 |
| Gemini 키 노출 | 가능 | 여전히 가능 |

마지막 두 줄은 **채점을 Cloud Functions 로 옮겨야** 해결됩니다.
Functions 는 Blaze(종량제) 플랜이 필요해서 카드 등록이 있어야 하고,
실제 사용량은 무료 한도 안이라 청구액은 사실상 0원입니다. 필요해지면 그때 진행하세요.
